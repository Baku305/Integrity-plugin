# Typing and validation

Read this reference when a mismatch may be turned into local permissiveness, or widening, normalization, or validation could change the contract that values are allowed to satisfy.

## Distinguish evolution from accommodation

A contract can genuinely broaden when the authoritative requirement includes more valid values or states. In that case its definition, validation, consumers, and verifier evolve coherently.

A local cast, dynamic type, optionality relaxation, schema widening, ignored diagnostic, or validation bypass is weaker when it only allows the current patch through while the authoritative contract remains stricter. These forms are signals to discriminate, not automatic errors: the right change may be a local translation or a correction to an overly strict verifier.

## Preserve an authoritative representation

Ask which contract actually owns valid values, which consumers may rely on it, and whether the changed verifier still distinguishes a valid broadening from an invalid state. A boundary normalizer can legitimately translate external variation before a stricter canonical contract; it should not create a parallel local semantics simply because conversion is inconvenient.

When the decision is really about which representation is authoritative, where conversion belongs, or which boundary separates two representations, architecture-integrity owns the structural decision.
